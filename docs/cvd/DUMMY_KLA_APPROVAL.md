# 保養 Dummy 的 KLA 與 PE 確認

每台設備一次使用四片 Dummy，PM1～PM4 各一片。設備製程判定通過、回槽後會自動送 KLA；所有膜厚與均勻度量測符合當輪門檻，PE 部門 Engineer／Leader 才可確認合格。PE 確認不會恢復加工。Engineer／Leader 在換回正式 FOUP、真空及異常處置互鎖全部成立後，另按「恢復加工」。

在保養面板查看各片進度，點「查看晶圓量測」開啟晶圓履歷 wafer map。PE 可填寫確認意見；退回必須填寫原因，接著重新跑完整四片測試。EE 與 Operator 不可確認 PE 資格。

量測缺片、失敗、過期或不合格都維持暫停。重新量測替換版本、改配方、再次保養或新故障使舊確認無效。新輪次不可拼接上一輪結果。普通正式片的量測仍只標示異常；此復機關卡只適用保養 Dummy。

## 部署與回退

先備份設備持久狀態、PostgreSQL 保養／量測／確認資料與映像版本，再部署支援 dummyApprovalModelVersion=1 的後端與 Go 設備，最後更新前端。舊 released 週期保留歷史；尚未復機週期缺少可關聯的量測須重新驗證。設備重啟依既有政策暫停模擬時鐘，必要時由授權人員恢復測試時鐘。

回退必須保留 dummy_confirmations 及保養鎖，尚未復機設備維持暫停，不可混用會略過 PE 檢查的舊後端與設備。量測更新及復機命令共用設備事務鎖，復機待執行時不可重新量測；設備另檢查週期、輪次與配方版本。

## 驗證

Go 保養及復機互鎖測試、Java 隔離 PostgreSQL 資格／PE 權限／版本替換測試，以及隔離 SECS/GEM、MQTT、Kafka、CVD、KLA 完整測試。測試資料不寫入正式批次。執行紀錄保存在 .runtime/dummy-*.log；正式部署後僅做讀取檢查，不以使用者現有批次做保養測試。

已通過 Go race、Java 單元測試、10 項隔離 PostgreSQL 測試、兩輪完整服務流程與介面角色／三語系／手機檢查。整合腳本在 tests/integration/dummy_kla_approval*.py 與 dummy_kla_approval_ui.cjs，固定使用 cvd-dummy-approval-test 與 localhost:18023，不得改為正式網址。

部署核對十台原有晶圓 ID、結果、位置與保養狀態保持一致，原本運行的模擬時鐘已恢復。已建立部署前映像標籤及狀態／資料備份；本次沒有在正式環境執行舊映像回退或資料庫還原演練。KLA 與製程結果皆為模擬資料，並非真實設備驗證。
