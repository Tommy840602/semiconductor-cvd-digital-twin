## Context

engine 的 active() 限制真空派片到最早批次，LL 預載目前允许後批先占單片槽。直接移除此限制可能令所有 LL 被待加工片占用而阻擋 PM 回收。

## Goals / Non-Goals

**Goals:** 就緒批次公平共享 PM、無死鎖、不中斷已有製程。

**Non-Goals:** 不增加手臂、LL 容量、配方或資料服務，不允許多片同占 LL。

## Decisions

真空派片依接受順序循環，記錄上次派片的批次 order，選擇其後第一個就緒批次，再繞回起點；只在成功派片後移動游標。大氣上料也輪流選 LL，先處理所有可回收片，再選一片上料。

可新增預載數量受空 PM 槽位限制，扣除已在 LL／大氣手臂中的待加工片及真空手臂預留 PM。與無限制預載相比，這保證待加工片都有可用 PM，避免占住唯一回收通道。既有檢查點已存在的過量預載，必要時退回 LP 釋放回收通道。

ModelVersion 升為 4，保留製程模型及所有晶圓，只新增排程游標預設值。故障以全域 dispatchPaused 停止新派片，僅把故障晶圓所屬批次設為暫停，不額外暫停無關的最早批次。

## Risks / Trade-offs

- 預載與回收競爭 → 預留空 PM、回收優先、75片守恆與有限時間結案測試。
- 排程語意改變 → 新變更明確取代舊整批 FIFO，UI 與現行測試同步更新。
- 升級中有晶圓 → 備份、載入時暫停、保存游標與製程，既有過量預載可退回原槽後再派。

## Migration Plan

先在隔離環境測試跨批次、暫停、故障及重啟，再備份正式檢查點及舊映像，更新 simulator/frontend，確認模型4與原有晶圓完整後人工恢復。啟動空閒 LP2／LP3；LP1 若已結案則建立新展示批次。回退使用保留映像，先排空或使用相容修正版，不覆寫唯一檢查點。
