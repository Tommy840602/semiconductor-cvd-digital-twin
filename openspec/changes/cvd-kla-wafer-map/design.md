## Context

現有 Go CVD 模型依 processRunId 保存五點合成膜厚；加工事件與回 LP 的 movement-complete 分開發生。Java Pipeline 保存事件履歷，既有十台設備白名單、統計與 3D 總覽均專指 CVD。動機見 proposal.md。本變更跨 Go、通訊、Java、資料庫與 Vue，需明確資料所有權及恢復策略。

## Goals / Non-Goals

**Goals:** 每個新完成且返 LP 的加工版本自動建立送測工作，透過一台共用站產生可重現的兩類量測結果與異常告警。

**Non-Goals:** 真實 KLA 驅動、型號認證、AMHS／FOUP 容量模型、新 3D 設備資產、自動品質放行、簽核、Email 或 Cp/Cpk。既有成功統計不等同量測合格。

## Decisions

### 1. 送測作為獨立後製程

Java 依已持久化的加工完成與返 LP 證據配對，不依目前快照猜測；鍵為來源設備、waferId、processRunId。補做使用新的 executionId／加工版本建立獨立來源。未返 LP、未完成、報廢及 PE 留片期間不送測；dummy 的成功完成也可送測，但保留類型，不混入產品統計。

送測採邏輯交接與模擬搬送延遲；不改寫 CVD 內的 LP／LL／PM 位置、不占用 CVD 手臂，不新增 CVD 之間搬運。這是展示用物流抽象，避免為 wafer map 引入實體載具排程。排隊頁顯示量測物流狀態而非宣稱 LP 實際搬離。

工作狀態為 waiting-transfer → in-transit → queued → measuring → completed；失敗為 awaiting-remeasure。資料庫持久化到站時間與單調入隊序號，同時到站依序號排序，一次一片。單站速度不足只增加量測佇列，不暫停 CVD。

### 2. 獨立 Go 站與通訊身分

部署一個 Go 量測 simulator 與配對 Edge Gateway，預設邏輯 ID KLA-SIM-01、equipmentType=metrology。延用專案的模擬 SECS/GEM 子集與 Sparkplug B，而非聲稱原廠協定。量測命令與結果沿既有雙向管線，新增隔離路由／topic 及身分白名單；不能直接把 KLA 加進固定十台 CVD 清單。Kafka metrology 事件與 CVD 統計消費隔離。

每項工作有 jobId，每次執行有 measurementId；Go 檢查點記錄已接受與已完成的執行，重送相同命令只回傳原結果。Java outbox、接收 inbox 與資料庫唯一約束負責至少一次傳遞下的去重。結果先持久化，再確認接收。連線過期顯示離線／資料過期，不能視為量測完成。

### 3. 合成量測模型與契約

每筆結果保存 modelVersion、seed、來源加工／recipe 版本、來源膜厚五點、量測設定及門檻快照。首版工程預設：300 mm 圓片、中心原點、x 向右／y 向上、notch 朝下，邊緣排除 3 mm；49 點固定極座標取樣（中心加三圈 8／16／24 點）。這些是可版本化的展示參數，不代表真實 KLA 規格。

膜厚以來源加工膜厚及五點偏差生成連續徑向／方向性分布，加上由固定 seed 決定的小幅量測擾動；不得把五點插值宣稱為新增實測。保存實際合成測點，畫面插值僅供視覺化。摘要含平均、最小、最大、半極差／平均的均勻度；平均為零時均勻度為 null。膜厚允差沿用來源門檻快照，缺失來源資料為 not-evaluated，不能造零。

缺陷用相同來源鍵及模型版本生成可重現的顆粒／刮傷／其他分類，含 defectId、座標 mm、尺寸 μm、刮傷路徑及合成嚴重度；不是從五點膜厚推斷真實缺陷。首版預設缺陷數超過 10 或任一尺寸超過 1 μm 為 review，配置及其版本隨結果保存。門檻僅為展示預設，無自動製程控制。每片上限 1000 缺陷，超過或截斷不得標完整；不包含缺陷影像。

### 4. 不可變結果與重測

PostgreSQL 保存 jobs、measurement runs、map JSON 與告警關聯；不把大量 map 寫進每秒 telemetry 或 Redis 快照。資料含 lot／slot、waferId、來源設備／PM、processRunId、executionId、recipeVersion、measurementId、revision、前次量測 ID、時間、兩類圖完整性、兩類判定與總判定。兩類資料都合法且完整後，單一交易公布 completed；超規 review 仍是完成，不等於通訊失敗。

重測由 Engineer／Leader 在網站提出，需 CSRF 與冪等鍵，沿用原來源加工快照，建立新 measurementId 與修訂，排入隊尾；Operator 可讀不可重測。技術重送沿用 measurementId，不能偽裝成新量測。舊結果永不被覆蓋；後續正常不刪除前次異常。這沿用既有工程操作權限，避免把品質結果直接接上簽核。

首版完整結果保留最近 30 天，UI 標明範圍；進行中工作及未結案告警引用資料不由清理任務刪除。清理採關聯安全交易，已過期顯示過期而非空白合格图。未在啟用期間送測的歷史晶圓顯示未量測，不批次補造。

### 5. 網站與告警

晶圓履歷加上獨立量測狀態與入口；詳情有膜厚／缺陷 Tab、圖例、色階、測點／缺陷點選、判定原因與版本選擇。同一晶圓不同測量可並排比較，相同座標與色階；不相容模型／座標時提示而不強算差值。手機使用點選，鍵盤提供可操作的點列表。支援繁中、英文、日文，保留 ID 與單位。

只在完整結果 review 時按 measurementId 建立一筆站內品質告警，列出兩類超規原因並連往該結果；量測通訊／資料錯誤另標待重測，不冒充品質超規。不建立 Email 事件、補做案件或控制命令；既有告警確認權限沿用。告警顯示來源 CVD 與量測站，避免誤認 CVD PM 故障。

## Risks / Trade-offs

- [單站佇列增長] → 到站 FIFO、分頁查詢與積壓指標；容量測試以十台 CVD 全速來源驗收，不用丟棄工作掩蓋壓力。
- [事件亂序、重播、重啟] → 持久化證據配對、唯一來源鍵、outbox/inbox 與 Go 檢查點；故障注入測試。
- [大型 payload] → 首版 49 點／1000 缺陷有界契約，端到端驗證 HSMS、MQTT 與 Kafka 大小限制；超限拒絕，不靜默截斷。
- [物流抽象與真實設備差異] → 明示模擬送測，CVD 位置與量測工作狀態分列；不承諾實體搬運精度。
- [缺陷判定被當作製程真值] → 固定模擬標籤、來源與門檻版本，與加工 success/scrap 分離。

## Migration Plan

1. 備份 PostgreSQL 與 CVD 檢查點；新增資料表、索引與契約版本，先保持功能關閉。
2. 部署相容後端、獨立量測站／gateway 與 UI，在隔離環境驗證完整管線、斷線、重播及資料大小。
3. 記錄啟用時間／來源界線，只對啟用後符合條件的工作送測；升級前結果顯示未量測。
4. 啟用後驗證十台 CVD 原加工、統計、簽核與保養不變；未啟用 Email，不操作正式晶圓來造測試資料。
5. 回退先停新工作派送，保留佇列、結果及檢查點，再回退 UI／服務；不刪資料表、不清 volume。重新啟用從原工作狀態續行。
