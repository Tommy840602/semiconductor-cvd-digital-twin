## Context

前端 Vue 3 JavaScript 尚無國際化資源層，App.vue 使用中文 tab 值判斷頁面，statusGlow 狀態名稱及各 Panel 的標籤分散定義。日期混用瀏覽器預設與 zh-TW／Asia/Taipei。後端 Identity 包含角色、部門及 authVersion，沒有 locale；API 錯誤與部分設備原因直接使用中文。通知已具備地址去重、資格重驗、有限重試與停用部署開關。

## Goals / Non-Goals

**Goals:** 切換僅改呈現；加工、派片、處方草稿、簽核權限與真實事件語意保持一致。三語資源可驗證、可維護，Email 可追蹤實際使用的語言。

**Non-Goals:** 不提供自由文字機器翻譯、翻譯管理後台、廠區時區切換、設備協定改版或真實寄信啟用。不翻譯使用者內容、recipe 自訂名稱、識別碼或工程單位。

## Decisions

### 1. 共用資源與固定識別碼

採集中式三語訊息字典與 Vue reactive locale，提供 t(key, params)、日期與數字格式化介面；實作時採用支援 Vue 3 的國際化工具並鎖定相容版本，禁止以全文搜尋取代中文字串的方式判斷語意。頁面值改為 overview/history/alarms/disposition/accounts 等固定識別碼，顏色／動畫狀態仍用原固定代碼。語言資源首版隨應用載入，避免切換時畫面等待網路。

所有一般文字、placeholder、aria-label、tooltip、SVG／Canvas 標籤、圖表圖例及 3D 提示納入字典；Canvas 標籤變更時重繪文字材質，釋放舊材質，不重建整個場景。`document.documentElement.lang` 同步為 zh-Hant、en、ja。翻譯字串視為文字，插值跳脫，不執行 HTML。缺少 key 回退繁中；繁中亦無 key 時顯示通用可讀文字並在開發檢查報錯，不顯示內部 key。

### 2. 偏好優先序與保存

支援代碼 zh-TW、en、ja。未登入採有效 localStorage 選擇，沒有時預設繁中，不自動猜測或覆蓋使用者選擇。本次登入頁手動選擇的語言在登入成功後保存至帳號並沿用；未手動選擇或重新整理時以資料庫帳號偏好優先，既有及新帳號預設 zh-TW；切換成功同步瀏覽器偏好。新增 app_users.locale，透過獨立 GET/PATCH /api/auth/preferences 讀寫自己的偏好；沿用登入與 CSRF，不接受目標 userId，不限制 Engineer／Leader。避免改動 Redis session 的 Identity 結構，也不因語言設定遞增 auth_version。

登入後先等偏好讀取再展示主畫面；保存失敗維持原語言並提示，不宣稱跨裝置已保存。其他裝置於下次載入／登入讀取最新值，不新增即時跨裝置推播。登出保留本瀏覽器已選語言。語言更新不能觸發加工命令、重新載入頁面或關閉處方／簽核草稿。

### 3. 系統訊息與歷史相容

後端新增穩定 code、params，同時保留既有 message 欄位供舊前端。前端依 code 翻譯，HTTP 狀態與權限判斷保持原值。Go 模擬設備產生的固定原因亦需盤點：優先使用既有事件／狀態代碼；需要補充的 reasonCode/params 採可選欄位並保留原 reason，不更動傳輸 envelope 版本或控制語意。

既有歷史資料不回寫翻譯。已知舊版系統原因使用明確相容映射；無法辨識的舊／外部訊息保留原文並標示原始訊息，不以推測性翻譯掩蓋診斷內容。人員輸入的原因、備註、名稱及核准證據不套用系統文字映射。

### 4. 日期、數字與流程

所有顯示格式使用所選 locale 與 Intl，時間明確指定 Asia/Taipei 並標示 UTC+08:00／對應語言的台灣時間。日期篩選、今日／昨日區間、稼動率分母與歷史查詢仍依既有台灣日界線；API 繼續傳 ISO／數值，不把顯示字串送作控制參數。秒數、膜厚等輸入與驗證維持既有精度與範圍。

### 5. Email 語言與共用地址

在寄送資格重驗後、第一次實際寄送前，從仍合格的原始收件帳號選取 locale；合格帳號語言一致則使用該語言，若不一致則回退 zh-TW，記錄共用地址語言衝突原因。這是保留每事件每地址一封規則的預設取捨，不依語言拆成多封。

在首次嘗試前原子保存 delivery locale、template version 與已渲染的主旨／本文；後續自動或人工重試沿用同份內容，方便釐清 unknown 及可能重複郵件。語言偏好變更不使 email_version 或 auth_version 改變、不取消工作、不重送 accepted。尚未開始寄送的工作採最新合格偏好；已開始的工作保留原語言。舊工作尚無語言時依同規則建立，已結案舊紀錄保留原狀。

Email 翻譯固定模板與狀態，維持站內登入連結、台灣時間與原始識別碼；不繞過自審／部門限制。不因本次部署修改 EMAIL_ENABLED 或觸發授權／實寄。

## Risks / Trade-offs

- 英文較長、日文字型不同 → 桌面／手機檢查導覽、對話框、表格、圖表及 3D 提示的換行與截斷。
- 中文被用作邏輯值 → 先遷移固定代碼，再做翻譯；驗證深連結、Enter／Esc、PM 選取與頁籤切換。
- 舊版自由格式系統訊息無法可靠翻譯 → 保留原文並標示；新訊息使用代碼，避免誤譯人員證據。
- Email 同地址多語偏好衝突 → 可見的繁中回退，維持原去重語意。
- 重新建立元件導致草稿或場景遺失 → 不以 locale 作元件 key，不因切換重啟連線／模擬。

## Migration Plan

先新增帶預設與允許值約束的帳號 locale、可選通知內容欄位；後端相容舊前端。完成字典與 code 化、三語驗證後建置 Docker 映像，備份並部署，不變更設備資料。回退應用映像即可，保留新增欄位與偏好；舊版繼續顯示繁中。通知服務開關沿用部署前值，測試只用假郵件服務。
