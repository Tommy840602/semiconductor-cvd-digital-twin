## Why

異常晶圓目前只有清零完整重做或報廢，無法保留既有膜厚進行受簽核的精準補做。需要 EE 提出排錯與單片處方、PE 核准直接觸發執行，讓每次追加加工具有可追溯的責任與設定依據。

## What Changes

- 帳號新增 EE／PE 部門，與 Operator／Engineer／Leader 角色分開判斷；Leader 管理帳號部門。
- EE Engineer 提交指定異常晶圓的排錯紀錄、目前膜厚、目標膜厚及所選步驟秒數。
- PE Engineer 核准即建立執行意圖；互鎖未滿足則顯示等待原因，滿足後自動執行，無第二次人工執行按鈕。
- 僅依預熱、穩定化、沉積、吹掃原順序執行勾選步驟；保留既有膜厚，只追加沉積，不修改整台 Recipe。
- 提案版本不可變，修改須重新送審；保存退回／核准、前後數值、執行指令與加工結果。
- **BREAKING**：異常晶圓的清零 rework 不再可由一般控制 API 直接執行，改走本補做簽核流程；既有歷史不刪除。報廢仍沿用既有權限，並使該片未執行的補做單失效。

## Capabilities

### New Capabilities

- `cvd-wafer-recovery`: 部門分工、單片補做版本、簽核與執行生命週期、膜厚保留及歷史串連。

### Modified Capabilities

無；主規格庫目前為空。本變更補充已完成 cvd-rbac 的部門維度，取代舊異常清零重做入口，但不重寫先前變更的歷史文件。

## Impact

Vue 帳號與異常處置／簽核畫面；Spring 登入身分、授權、簽核 API、交易與指令發布；PostgreSQL 部門／提案／版本／審核及執行意圖；Go 補做狀態機、沉積累積與檢查點；MQTT／Kafka 契約增補補做關聯欄位，TimescaleDB 保存補做數值。沿用現有服務與 LL 單片、雙手臂、三批並行限制。
