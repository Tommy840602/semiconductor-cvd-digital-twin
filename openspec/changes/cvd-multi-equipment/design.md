## Context

參見 proposal.md。Go 目前載入單一 state.json；閘道 MQTT 路徑、Java 快照查詢與 Redis 鍵固定 CVD-01，製程查詢以 PM／LL 名稱篩選。既有多批輪流派片已取代早期整批 FIFO；補做意圖包含版本與膜厚基線，擴充時不可弱化此契約。

## Goals / Non-Goals

**Goals:** 明確綁定機台身分，維持既有單機行為與資料追溯，讓一台離線、故障或重啟不阻止其他台運作。

**Non-Goals:** 不增加跨機搬送、全廠批次自動分派、跨機原子控制或新的機台別帳號授權；現有角色與 EE／PE 部門規則延用所有機台。

## Decisions

### 1. 獨立模擬與共用服務

採十組參數化 Go 模擬器／閘道容器，每組以 EQUIPMENT_ID、OPC 端點與獨立持久卷設定，Compose 共用映像與設定模板。所有組共用 Java、MQTT、Kafka、PostgreSQL、TimescaleDB、Redis。相比單程序十個引擎，容器隔離可直接演練單機斷線與重啟；相比複製十套後端及資料庫，避免不必要資源成本。每台保留原本三批輪流派片、單片 LL、兩組手臂及四 PM。

### 2. 身分與雙向路由

機台登錄表限定十個完整編碼；模組 ID 保留 PM1／LL1 等局部名稱，身分由 equipmentId 與局部 ID 組成。訊息外層 equipmentId 一律指完整機台；製程 API 現有代表 PM／LL 的 equipmentId 欄位改為 moduleId，避免語義混淆。事件 ID、指令 ID、加工與補做執行 ID 使用全域唯一值，同時保存機台歸屬。

MQTT 使用 cvd/{equipmentId}/{topic}；閘道僅訂閱自己機台，驗證指令身分後才呼叫 OPC UA。Kafka 依機台分區鍵保持同機順序；後端比對 topic 與 payload 機台，不符則隔離記錄。去重、epoch、版本比較、ACK、斷線緩衝及重播皆按機台處理。Redis 使用 cvd:{equipmentId}:latest／heartbeat；登入 session 仍共用。

### 3. API、儲存與簽核

單台 API 採 /api/equipment/{equipmentId}/...，總覽採 /api/equipment；所有命令、歷史、曲線、recipe、告警、簽核及執行狀態查詢由後端限制機台。舊無機台控制入口升級後拒絕，不預設操作 01。WebSocket 訊息攜带機台；總覽訂閱摘要，詳情只接收所選機台資料。

資料表新增 equipment_id 及適用外鍵／複合索引，歷史與遙測以機台、時間及局部目標查詢；Timescale 唯一鍵配合時間分區約束。既有物件 ID 不重編，新增物件使用全域唯一識別；不可僅憑 waferId 或 PM1 查詢及更新。補做申請、版本、意圖、指令、結果均綁定同一 equipment_id，核准時與設備執行前重驗晶圓、PM、基線和版本。不允許改機台沿用原核准。

### 4. Recipe 版本與複製

各機台維護不可變 recipe 版本及當前有效版本。複製以來源版本快照建立目的台新版本，保存來源機台／版本、目的機台／版本、操作者、時間與完整設定，不建立後續連動。02 至 10 初始取得現行有效 recipe 的獨立副本（記錄初始化來源），保持空機；01 保留目前有效設定。

修改與複製沿用 Engineer／Leader 權限及參數驗證；目的版本須樂觀鎖比對，衝突不得覆蓋。複製不啟動批次、不解除故障、不改已核准單片處方。加工開始時固定使用 recipe 版本，後續修改只影響新開始的加工，履歷保留實際版本；既有設定安全限制仍適用。

### 5. 前端呈現

總覽十張設備卡顯示完整編碼、連線／暫停／故障、加工 PM 數、成功與報廢量；失聯狀態不算正常即時產量。點擊進入現有單台畫面，保留配色、圖形、hover 詳情及按需 Lot 顯示。切換時取消舊查詢、清除對話框與曲線並檢查回應機台，避免遲到資料覆蓋。操作表單綁定開啟時機台，切換後失效；手機提供單欄卡片與機台選擇。

## Risks / Trade-offs

- 十台每秒採樣使資料量接近十倍 → 共用服務但只推送總覽摘要／當前詳情，測量寫入率與磁碟每日增長，驗證 30 天保存與清理；不任意降低已承諾採樣率。
- 同名模組或漏加機台篩選造成串台 → 機台身分必填、後端所有資料路徑稽核，加入兩台相同局部 ID 的負面測試。
- 十組容器耗用更多記憶體 → 共用映像及 Compose 模板，部署前量測資源；故障隔離的代價可見且可調整資源限制。
- 遷移中的舊訊息重送與待執行簽核 → 維護期間停止推進與新指令，舊 CVD-01 訊息僅經明確遷移映射指向 01，保留原事件內容與唯一 ID，重送不得執行兩次。

## Migration Plan

1. 記錄版本、各表筆數與活動批次／晶圓／簽核狀態；備份資料庫、模擬器與閘道卷並驗證可還原。暫停設備推進及新操作，停止舊服務寫入並盤點 MQTT／Kafka／outbox 未完成資料。
2. 執行可重跑的 schema 與資料遷移：舊資料新增歸屬 01，保存 CVD-01 對應表；原歷史 payload 及簽核版本原文不覆寫，以新歸屬欄與讀取映射解決旧身分。舊未完成命令與意圖按原 ID 綁定 01，去重資料一併保留。
3. 將舊 state.json 及閘道緩衝遷移至 01 專用卷，保留晶圓位置、膜厚、輪流游標與補做進度。初始化 02 至 10 空機與独立 recipe 副本，不注入演示批次。
4. 配套部署新版全鏈路，01 保持暫停等待人工恢復，02 至 10 待命；重建機台快取，處理遷移前積壓並驗證數量守恆、履歷及簽核對應，再開放網站操作。
5. 冒煙及隔離驗證失敗時停止新版寫入，保留新版資料副本，還原整組遷移前資料庫／卷與映像。已產生新業務資料時不得直接覆蓋回滾，先匯出並對帳；不允許舊版服務連接已遷移資料继续操作。
