## Implementation Notes

模型、完整復機流程、後端與介面已實作。Go（含 race）、Java 資料庫測試、Vue 測試與三語手機瀏覽器驗收通過；隔離 SECS/GEM → Sparkplug B → Kafka 全流程、MQTT／Kafka 重連、測試中斷與四 PM Dummy 復機通過。展示站已部署並通過十台新鮮資料、30 組泵浦、原有晶圓／腔體／配方／暫停狀態保留、KLA 查詢、三語／手機介面及公開網址驗收。為處理實際積壓，補上 inbox 待送索引及每批每台最高版本快照合併；逐秒歷史與事件不合併。

已確認設計：若三組 LL 泵浦全部故障且 PM 尚有晶圓，既有「排空後才保養」形成循環阻擋。使用者已同意新增「全台暫停、空 LL 隔離後受控修復一組回收通道，再排空與完成整台保養／Dummy」；納入本次實作與多泵故障驗收。

驗收證據：`.runtime/phm-stack-proof.json`（受控回收、保養、抽氣中斷、四 PM Dummy 與人工復機）、`.runtime/phm-production-proof.json`（十台／三十泵浦與既有資料保留）、`.runtime/phm-kla-production-proof.json`。資料庫完整備份與十台 checkpoint 位於 `.runtime/backups/phm-20261002`；已驗證備份目錄、校驗碼、schema 及帳號／配方資料還原，未宣稱完成大量歷史表的全量還原演練。

十台回放效能補強：Bridge 依機台保持順序平行落盤、受限事件回放、SECS 原始 JSON 重用、快照／通訊狀態批次更新、Redis pipeline、首頁批次讀取與快照 LZ4 壓縮；加入競態、精度、單機阻塞隔離與資料庫亂序回放測試。
