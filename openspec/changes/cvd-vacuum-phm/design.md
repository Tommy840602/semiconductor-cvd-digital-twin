## Context

動機見 proposal.md。simulator/process.go 的 LL 壓力以固定三秒內插；engine.go 的倒數結束會直接切換壓力與搬送階段。新增退化不能只改圖表，必須同時替換正常抽氣完成條件。maintenance.go 的 drained 與 maintenanceBlockers 要求 LL、PM、手臂排空；抽氣故障的留片回收是必要整合點。

既有保養、異常處置、SECS/GEM 傳輸、多語言及 KLA 規劃均保留。本次跨越模擬器、資料契約、後端與介面，因此需要設計文件。

## Goals / Non-Goals

**Goals:** 讓相同版本與輸入能重現泵浦退化；健康提示與控制互鎖共用設備端事實；保養、測試、恢復均可追溯且可在重啟後繼續。

**Non-Goals:** 不以隨機正常值訓練真實 RUL，不推論實際 TEL 配置；不新增服務或繞過現有 EE／PE／Leader 異常簽核。KLA 資料僅維持既有用途。

## Decisions

### 1. 每個 LL 的版本化模擬模型

泵浦以 equipmentId + LL ID 唯一識別。checkpoint 保存 lifetimeCycles、cyclesSinceService、wear、serviceGeneration、modelVersion、活動 cycleId、經過時間、壓力及故障鎖。每次有效抽氣啟動只累計一次，正式、Dummy、空腔測試均計入實際使用；暫停與重啟不另計次。

採可解釋的確定性效率模型，避免直接隨機產生健康分數。初版工程預設（非實機門檻）：wear 每次增加 0.001 並限於 0～1，efficiency=max(0.1,1-0.9*wear)，抽氣壓力 P(t)=1013*exp(-ln(1013/0.01)*efficiency*t/3) mbar。單次啟動凍結模型參數，目標 0.01 mbar、逾時 12 個模擬秒；先判斷達標，再判斷逾時。健康狀態以精確值決策，不使用畫面四捨五入值。暫停凍結模擬秒，採樣時間仍為實際時間。

health=100*(1-wear)，wear>=0.6 預警；剩餘抽氣次數為以同模型推算下一次預期耗時超過逾時門檻前的可成功次數（非日曆壽命），測試覆蓋邊界。所有參數採版本化設定，執行紀錄保存快照；不是 recipe step，也不新增 Operator 可改參數介面。工程預設可在驗收前校準並一併更新測試及文件。

### 2. 失敗鎖與排空不形成循環等待

預警只建事件，不暫停。實際失敗鎖住該 LL 的正常搬送並設定整台 vacuum hold；其他健康在製片可沿可用 LL 完成回槽，不新增正式派片。失敗片保持身分、槽位來源與加工結果，不自動成功、報廢或補做。

Engineer／Leader 可提交受控回收，設備確認雙側隔離、手臂無搬送、來源槽可回收後，允許故障 LL 執行專用排氣；實測模擬壓力到大氣條件後才經 ATM 回原 LP。不是解除正常搬送鎖；條件不符保持留片並顯示阻擋。真空側門在整段回收保持關閉。回收指令包含 cycleId、故障 generation 與 commandId，設備重新驗證。回槽不變更加工品質或既有簽核狀態。

泵浦故障允許在排空後進入修復保養，不把「泵浦尚未修好」作為進入修復保養的前置條件。既有 PM／晶圓異常簽核仍獨立阻擋；泵浦空腔故障不建立虛構的晶圓補做單。vacuum hold 到測試、Dummy、其他異常放行與手動恢復全部成立才解除。

### 2.1 全部回收通道失效的受控修復

使用者已確認：提供 vacuum-service-channel 指令，在 vacuum hold、整台停派、目標 LL 無片、無手臂占用、排氣至大氣且無其他活動泵浦測試時，修復指定泵浦並自動啟動空腔回收通道測試。指令綁定故障 generation 與 cycleId，保留原退化／故障與操作證據；修復只改該組泵浦，needsService 持久標記確保後續整台保養必須包含此泵浦。

測試通過且排氣完成才可成為回收通道；不允許進新片。已完成晶圓可經任一可用 LL 回原 LP，LL 暫時回收用途不得改寫批次原本綁定或跨機台搬送；原故障 LL 若仍留片，須先受控排氣回收。若測試失敗，保持真空 hold，可在重新排氣與新故障版本確認後再修復。所有 PM 晶圓排空後仍須整台保養、所選泵浦測試、四 PM Dummy 及手動復機，既有 PE 留片及 Leader 放行要求照常。

### 3. 選擇泵浦的保養證據

沿用整台保養週期，增加 selectedPumpIds 與各泵浦 serviceGeneration。只能選本台 LL，進入保養後固定集合；結束保養才一次性重設所選 wear 與 cyclesSinceService，終身次數、舊曲線與事件不刪除。重送同命令不二次重設。未選擇的故障泵浦仍阻擋復機。

保養後待機且派片保持暫停。由 Engineer／Leader 啟動所選 LL 空腔抽氣測試：每組從大氣壓、門關閉、無片開始，壓力達標且不逾時才通過，最後回到可用空腔狀態。測試輪次绑定保養週期、所選集合、serviceGeneration、模型版本；任何失敗、中斷或缺證據皆不通過。重測須所選泵浦在同一輪全部通過，不拼接舊輪次。

全部通過才允許既有四 PM Dummy，沿用 recipe 快照及整輪有效性。新故障、再次保養、模型變更使泵浦測試與後續資格失效；recipe 變更依既有規則使 Dummy 失效。復機在設備端原子重驗最新版本，維持既有角色、部門與異常放行要求；一般 resume 不可繞過。

### 4. 傳輸與儲存

沿用 SECS/GEM → Edge Gateway → Sparkplug B → MQTT-Kafka Bridge → Kafka；加法式加入 pump snapshot 與 cycle/service/test/alarm 事件。snapshot 含 sample time、模型版本、狀態與資料有效性，事件含 equipmentId、pumpId、cycleId、eventId、source sequence、generation、時間、用途與結果。指令沿用既有簽章、期限與設備目標驗證。

TimescaleDB 每實際秒採樣保存壓力與狀態，保留 30 天；PostgreSQL 保存週期摘要、告警與保養／測試稽核證據，沿用既有稽核保留政策，不隨採樣清理刪除。Redis 僅快取。依事件識別去重、來源序號阻擋倒退；終態事件優先於舊 snapshot，不以 API 收到请求等同設備執行完成。達標率以範圍內已結束的成功／失敗週期為分母，中斷另列，零週期顯示無資料。

### 5. 介面與權限

在既有分頁組織加入真空 PHM 檢視，提供 30 組概覽及選定機台的三組趨勢、預警原因、抽氣達標率、保養標記與剩餘次數依據。資料過期顯示未知與最後時間，不沿用綠色健康判定。首頁與 3D 摘要補充真空預警／故障，不覆蓋更高優先故障、保養或資料過期狀態，不新增一排首頁大卡。

Operator 可讀；Engineer／Leader 可回收、選擇保養、測試及有條件恢復。後端與設備雙重驗證，稽核操作者及結果；全部文案沿用繁中／英文／日文。歷史無資料不補造退化曲線。

## Risks / Trade-offs

- 模擬剩餘次數可能被當真實壽命 → 顯示模擬標籤、模型版本與假設，不宣稱統計信心水準。
- 失敗 LL 留片造成保養死鎖 → 專用受控排氣回收與分開的修復／復機條件，測試 inbound、outbound 與空腔情境。
- 高退化增加加工等待 → 由物理模擬時間控制排程，預警本身不改排程，驗收使用隔離資料與加速 fixture。
- 舊 snapshot 與重送指令重設狀態 → generation、事件去重、設備端條件檢查與持久化 checkpoint。

## Migration Plan

先備份資料庫及十台 checkpoint；先部署可讀新舊資料的後端及介面，再部署模擬器／傳輸映射。舊 checkpoint 缺泵浦資料時初始化健康模型，明確記錄啟用時間，不倒推過去使用次數；已在抽氣的舊週期依原規則結束，下一週期才用新模型。

在隔離環境驗證 30 組隔離、故障回收、保養與重啟後，再於維護窗口啟用。回退程式前停止派片並備份新狀態；存在 PHM 留片或 hold 時禁止直接換回不識別 hold 的舊模擬器。必須先完成受控處置或維持設備停用，資料表與歷史保留。
