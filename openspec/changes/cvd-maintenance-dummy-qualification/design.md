## Context

參見 proposal.md。現有模擬器以正式 Lot 及 LP 綁定，尚無載具暫存模型；單片 LL 與 ATM／VAC 手臂皆有占用互鎖。現有異常處置要求 EE 提案、PE 確認及獨立 Leader 放行，利用率以實際加工秒數計算。保養新增跨服務狀態及資料模型，需本設計說明持久化與防繞過方式。

## Goals / Non-Goals

**Goals:** 在既有設備配置內完成排空、載具交換、四腔體驗證及手動復機；保留正式批次進度與既有異常流程。

**Non-Goals:** 不新增實體 LP、跨機台搬送或真實硬體維修；不自動簽核異常、不將 Dummy 結果當作實際量測認證；不改「PM 使用率」名稱。本變更不包含另行調整涵蓋率四捨五入顯示的工作。

## Decisions

### 狀態與獨立阻擋

每台持久化 maintenanceId、generation、phase、selectedLP、暫存載具及 qualificationRunId。對外狀態依序為：待排空、保養中、待機／待驗證、Dummy 驗證中、測試未通過或驗證通過待換回、可手動恢復、已結束。載具交換是獨立且可追溯的狀態，不用 phase 字串取代晶圓占用互鎖。

申請即建立 maintenance hold，阻止所有正式派片及新正式批次進入。排空僅完成已離開 LP 的晶圓，包含尚在搬送或 LL 的投入片；沒有投入的等待片留在 FOUP。所有 PM、LL、手臂清空且無未解互鎖時才進入保養中。異常晶圓先完成既有簽核回收流程，不以保養強制清空。

正式派片條件須同時滿足一般派片條件、保養鎖解除及異常鎖解除。既有 equipment-release 只解除異常鎖；即使原流程曾直接恢復派片，有保養鎖時也只能回到保養流程。resume 只在當次資格有效、載具復原、無故障且無異常放行待辦時原子解除保養鎖。recovery-clock 只恢復必要時鐘，不解除保養鎖。結束保養不自動啟動測試或復機。

### FOUP 交換

使用者在排空後選擇一個 LP。若有正式 FOUP，建立持久化 carrier parking 紀錄，保存原 LP、lotId、carrierId、槽位映射及派片游標；以載具是否停靠判斷可派片，不能只看 wafer.location 的 LP 字串。UI 明示「已暫存」，不把停靠測試載具的槽位畫成正式晶圓。

正式批次資料仍保留，不清空 Lot、不改成功／待加工結果。載入 Dummy 載具前，設備再次檢查全機排空、選定載具全部回槽與沒有在途搬送。交換指令以單一持久化交易更新停靠與暫存狀態，重送同一命令不重複建立載具。僅為模擬人工 FOUP 換載，不用手臂搬動整個 FOUP。

測試載具四片放在槽位 1～4，依序綁定 PM1～PM4；通過現有 ATM → LL → VAC → 指定 PM，再經原路回到測試載具。三個 LL 維持單片容量、雙手臂共用，不瞬移晶圓。全部測試片回收後才可卸下；正式 FOUP 必須回到原 LP，原為空則恢復空位。復機要求載具交換完成。

### Dummy 身分、配方與重測

晶圓／載具新增用途 production 或 dummy，舊紀錄預設 production。Dummy 以 equipmentId、maintenanceId、runId、PM 產生唯一識別；正式 Lot 清單、在製批次數、成功／報廢數與輪流派片不納入測試載具。共用加工與搬送引擎，Dummy 派片使用指定 PM 的獨立佇列，正式佇列維持鎖定。

啟動每輪測試時凍結當台 recipe 版本及 step 秒數，沿用既有膜厚、均勻度合成品質判定並保存門檻與結果；完整步驟完成且 quality=pass 才通過。測試執行中禁止修改該台 recipe；待測試／已通過時可依原權限修改，但必須使原資格失效，禁止驗證舊配方後套用新配方直接復機。

重測建立新 runId 及四片新 Dummy，在前輪全部回收後再次載入；每輪結果保留，不跨輪拼接。單純品質未通過可正常回收並保留不合格結果；設備故障或留片異常仍走既有異常處置，Dummy 在簽核畫面標示用途，不能自動宣稱回收成功。保養、故障或配方變更增加 generation，已完成的歷史結果不刪除，但不得作為新 generation 的復機資格。

### 通訊、權限與持久化

沿用已簽署控制與設備命令去重：maintenance-request、maintenance-end、maintenance-carrier-load、qualification-start、maintenance-carrier-restore 及受條件限制的既有 resume。所有命令帶 equipmentId、maintenanceId、expectedGeneration 及 commandId；後端檢查 Engineer／Leader，設備檢查狀態與互鎖，拒絕陳舊 generation、跨設備或重播解除鎖。

PostgreSQL 保存保養週期、狀態轉換、載具交換、測試輪次及每 PM 結果；透過現有 outbox 及事件去重保存命令意圖與設備執行證據。Go checkpoint 才是派片互鎖最終依據，Redis 僅快取。未完成週期及其載具／簽核關聯不得因一般歷史清理被刪除；完成週期沿用專案歷史保留政策。

SECS/GEM 事件及 Sparkplug B 狀態擴充攜帶保養階段、驗證摘要、用途與 generation；斷線畫面標示資料品質，不能用舊資格放行。重啟保留載具、晶圓與鎖，模擬時鐘仍依既有規則保持暫停，經有權限的恢復時鐘操作後續行測試，不自動開始正式加工。

### 利用率與 UI

保養待機等有效樣本四 PM 加工旗標為 false，統計分母維持牆鐘時間；Dummy 實際執行步驟沿用 utilization 樣本，保持「有加工」既有定義，品質結果不影響已發生的加工秒數。用途與保養週期另保留於歷史以便追查，不把保養當成資料缺口。

首頁與 3D 的保養狀態以明確 badge 呈現，不用改 PM1～PM4 名稱。故障與通訊過期提示優先可見，不能被保養色彩覆蓋。製程畫面提供申請／結束保養、選 LP 換載具、啟動四片測試、各 PM 結果、換回 FOUP 與手動恢復；條件不滿足時列出實際阻擋原因，Operator 僅能查看。

## Risks / Trade-offs

- [一般 resume 或異常放行繞過保養] → 共用設備層派片判定，兩種鎖獨立保存，所有解鎖路徑測試。
- [正式 FOUP 暫存後晶圓仍顯示原 LP 導致誤派] → 排程必須驗證 carrier 停靠關係，UI 分開顯示停靠與暫存，逐片比對換載前後身分及槽位。
- [Dummy 故障形成留片] → 保持原異常處置回收流程，只有回收完成才允許重測及換回，不新增跳過簽核的清片入口。
- [測試結果不適用新配方或新故障] → 以 generation、recipe 版本及單一 runId 驗證四 PM 結果，原子判定後才接受手動復機。
- [模擬品質不代表真實檢測] → 顯示模擬驗證及當次門檻，保留量測來源資訊，不宣稱實際設備認證。

## Migration Plan

1. 備份十台檢查點及歷史；新增相容資料表與用途欄位，舊晶圓歸 production、沒有保養紀錄的設備維持既有行為。
2. 先部署能保存與傳輸新狀態的後端及通訊元件，再部署設備狀態機及 UI；資料不完整的混合版本不得開放保養／測試指令。
3. 在隔離環境跑完三 LP 全占用、故障留片、四片測試、重測、配方變更與重啟驗證，再更新展示環境；不替使用者開始保養、測試或恢復加工。
4. 回退時若存在活躍保養或暫存載具，禁止直接載入不認識保養鎖的舊模擬器。先保持新設備服務及正式派片暫停，完成安全回收／換回，或以部署前完整備份恢復隔離驗證過的一致版本；不可只刪除保養欄位解除鎖。
