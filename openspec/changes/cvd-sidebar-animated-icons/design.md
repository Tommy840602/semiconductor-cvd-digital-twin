## Context

App.vue 前四個選單以字元陣列呈現圖示，異常處置對應空字串；帳號管理及登出分開渲染。前者有 Leader 可見條件，登出會卸載側欄。需統一圖示介面並處理 pointer、focus、click 重複事件，因此在實作前明確訂定互動規則。

## Goals / Non-Goals

**Goals:** 用一個可重用圖示元件涵蓋六種圖案及播放生命週期，讓各按鈕的排版一致。

**Non-Goals:** 不更動側欄品牌、帳號資訊、導覽順序、API、權限及機台狀態動畫；不為動畫延遲登出或導覽。

## Decisions

- 使用內嵌 SVG 與 CSS 動畫，透過 currentColor 沿用側欄色彩。相較 GIF 或動畫套件，可維持銳利線條、無外部資產請求，且容易支援減少動態效果。
- 圖示使用共同 24×24 viewBox 與固定寬高，按鈕以 flex 和固定 gap 對齊。SVG 使用 aria-hidden 與不可聚焦設定，文字作為可存取名稱，保留 focus-visible 樣式。
- 從按鈕轉送 pointerenter（排除觸控模擬移入）、鍵盤 focus-visible 聚焦與 click 觸發播放。每輪約 600–800ms；播放中忽略額外觸發，結束後可重新觸發。相較 hover 永久 class，不會持續循環，也能回應已聚焦按鈕的再次點選。
- 共用元件維護動畫開始與結束狀態，以 animationend 清除，必要備援計時器在卸載時取消。圖示各部件的 keyframe 定義局部作用域，避免與 statusGlow 動畫衝突。減少動態模式下不設置持續等待 animationend 的播放鎖。
- 保留 App.vue 的原事件處理函式與可見條件，圖示僅提供視覺回饋。登出成功時允許動畫隨側欄卸載中止，不增加登出延遲。

## Risks / Trade-offs

- 同一次點選觸發多種事件 → 播放期間合併事件，不疊加、不排隊。
- 小圖示過度複雜 → 統一線寬，僅移動少數部件，驗證窄螢幕清晰度。
- 動畫結束後圖案缺筆 → 所有圖示具備完整靜態基態，勾選描繪最後回復完整圖案。
- 裝飾回饋干擾功能 → 動畫不擁有業務請求，沿用原按鈕事件，回歸檢查權限與登出。

## Migration Plan

完成元件、接入與桌面／手機驗證後，僅部署前端。保存前一版前端映像及回退方式，無資料遷移；回退時還原前端映像即可。
