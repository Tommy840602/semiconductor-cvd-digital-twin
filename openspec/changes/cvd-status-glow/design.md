## Context

動機見 proposal.md。目前 cleanroom/navigation.js 已集中機台狀態優先序與 5 秒過期判定；CleanroomOverview.vue 使用該摘要，scene.js 在既有繪圖迴圈更新靜態標記色。EquipmentTopology.vue 使用 SVG 腔體外框與個別 PM 資料。3D 模型共用 InstancedMesh 材質，直接修改材質會影響多台機器。此變更跨首頁、SVG 與 Three.js，需共同視覺規則。

## Goals / Non-Goals

**Goals:** 將狀態判定與效果參數分離，使用同一套色彩與週期，讓過期判定即使沒有新訊息也能更新。

**Non-Goals:** 不新增後端狀態、不改加工或簽核、保養流程、不重新計算統計、不替歷史圖表加動畫、不更換模型。

## Decisions

1. 共用狀態描述包含穩定狀態 key、文字、色彩及週期。機台沿用既有 activeLots 等判定；PM 另以故障、全機暫停、實際 step／remaining 與晶圓結果辨識，保留待確認留片文字。比各元件獨立編寫配色更能避免不一致。全機派片暫停與批次暫停不可直接當成所有 PM 製程時鐘已停止，實作需對照既有 paused 語意。
2. 配色沿用綠 #21977f、黄 #c3a666、橘紅 #df855a、灰藍 #91a2a5。CSS 變數與 SVG 外框光暈承載 2D 效果；文字及選取框獨立於明暗變化。採平滑亮度變化而非整塊內容消失。加工用柔和呼吸，其他狀態使用較明確的明暗循環。
3. 3D 新增或擴充每台獨立的底座光圈及狀態燈，沿既有 requestAnimationFrame 依同一時間相位更新該台兩者的亮度。保留共用 GLB 材質；不採全場景 bloom，以控制效能與保持模型清晰。光圈不加入互動拾取目標。
4. 以持續更新的現在時間判定資料品質，不僅在 fleet 更新時運算。狀態改變立即切換效果；頁面隱藏與 tab 切換沿用 setActive，釋放新增材質、幾何及監聽器。避免為每台設備新增獨立計時器。
5. CSS 與 3D 同時響應 prefers-reduced-motion，改固定光暈；保留原互動與對比。相較新增設定頁，使用系統偏好可避免額外操作負擔。

## Risks / Trade-offs

- 共用模型材質造成全場變色 → 僅操作獨立標記與光圈，驗證十台不同狀態。
- 留片或派片暫停被誤判為加工停止 → 檢查既有資料語意，將實際 PM 製程與機台摘要分別測試。
- 光暈影響辨識或手機效能 → 控制亮度與範圍、不使用全場景後處理，實測桌面與手機。
- 灰藍過期提示較不醒目 → 保留明確文字及慢速週期，不沿用舊加工綠色。

## Migration Plan

先完成共用狀態及測試，再接入首頁／2D 和 3D，執行建置與互動驗證。僅部署前端映像，保留前一版前端映像供回退；無資料遷移，部署不觸發任何機台控制指令。
